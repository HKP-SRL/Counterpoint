**Scope and wording decisions** (interpretation of the owner decision; recorded so the owner can see the "why"):
- *Per machine, in the Counterpoint home.* gh's keyring entry belongs to the machine, not to a host. The record lives in `{home}/trust/accepted-risks.json`, next to the pinned key. Agent sandboxes deny both Read and Edit there (01-04 deny twins) and Bash cannot write there (Seatbelt). That sandbox denial is the boundary. The terminal requirement (TTY on stdin and stdout plus a typed `y`, as `trust-key` uses since 01-10) records owner intent. A source-scan test makes "only the terminal command writes it" checkable.
- *Two checks for applicability.* The verdict requires that the report recorded the entry when doctor ran (so the stored report shows it) and that the same entry (id and `recordedAt`) still exists now. So revoking takes effect at once in doctor and the API without a rerun, and a risk recorded after a check does not quietly turn that old check green.
- *Revoking needs no terminal.* It can only make the verdict stricter. It is idempotent and prints what it did.
- *The verdict names the state honestly.* `accepted-risk` is a third verdict, with its own words; the gh row keeps `Reachable`. (Phase 2 note, not part of this plan: Phase 2 is expected to treat `pass` and `accepted-risk` as passing.) Until 01-20 updates the console, the console reads any non-`pass` verdict as failing, so it never shows better than its data.
- *Schema stays v1.* The new report fields (`steps`, `leaks`, `trusted`, `acceptedRisks`) default to empty or false, so older reports and fixtures still parse. Missing evidence means the gh row can never qualify (fail closed).
