> Visual and interaction contract for Phase 1: Trusted Shell & Signed Runway. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | Astryx (`@astryxdesign/core`, MIT, beta 0.x) with prebuilt CSS. shadcn is not used (owner decision), so there is no `components.json` and no shadcn gate. |
| Preset | Theme package `@astryxdesign/theme-neutral` (restrained warm grays, Figtree, Lucide icons). Default pick under Claude's Discretion; swapping to another `@astryxdesign/theme-*` is a one-import change. |
| Component library | `@astryxdesign/core` subpath imports (`@astryxdesign/core/<Component>`), React 19, peer `@stylexjs/stylex ^0.19.0` |
| Icon library | Lucide via the theme's icon registry (`lucide-react`, installed as a dependency of `theme-neutral`). Use Astryx `Icon` / `IconButton`; do not import a second icon set. |
| Font | Figtree (named by `theme-neutral`), **self-hosted** through `@fontsource/figtree` (OFL-1.1, weights 400/500/600/700, latin subset). Monospace: the theme's `ui-monospace` stack for commands, hashes and diffs. |

Setup contract (prebuilt path, no StyleX build plugin in Phase 1):

1. CSS imports, in this order (it maps to the layer cascade `reset` then `astryx-base` then `astryx-theme`):
   `@astryxdesign/core/reset.css`, `@astryxdesign/core/astryx.css`, `@astryxdesign/theme-neutral/theme.css`, then the four `@fontsource/figtree/latin-{400,500,600,700}.css` files.
2. Do **not** import `@astryxdesign/theme-neutral/fonts.css`. It `@import`s Google Fonts over the network. Counterpoint is a loopback tool that must work offline and under a strict `default-src 'self'` CSP. Self-host the font files (they ship inside `@fontsource/figtree`, which declares `font-family: 'Figtree'`, matching the theme). `@fontsource-variable/figtree` declares `Figtree Variable` and does **not** match, so do not use it.
3. Providers at the root: `<Theme theme={neutralTheme} mode={mode}>` (`neutralTheme` from `@astryxdesign/theme-neutral/built`, `Theme` from `@astryxdesign/core/theme`) wrapping `<LinkProvider component={RouterLink}>` (`@astryxdesign/core/Link`) so Astryx links route through TanStack Router.
4. No custom `xstyle` / StyleX styles in Phase 1. Compose with Astryx props (`gap`, `padding`, `variant`, `elevation`). If a gap truly needs custom CSS, write one small plain stylesheet that uses only Astryx CSS variables (`var(--spacing-*)`, `var(--color-*)`); this avoids needing `@astryxdesign/build`. Hex values never appear in Counterpoint's own CSS.
5. Exact-pin `@astryxdesign/core`, `@astryxdesign/theme-neutral` (and `@astryxdesign/cli` if added as a dev tool) to the same version; it is 0.x and ships weekly. `npx @astryxdesign/cli component <Name>` prints full props for any component and is the executor's reference.

## Spacing Scale

All Counterpoint-authored spacing uses Astryx spacing steps (`--spacing-N`, 4px × N, rem-based so it grows with the reader's root font size). Declared values (multiples of 4):

| Token | Value | Astryx step | Usage |
|-------|-------|-------------|-------|
| xs | 4px | 1 | Icon-to-label gaps, badge inner gaps |
| sm | 8px | 2 | Compact element spacing, gap between a label and its value |
| compact | 12px | 3 | Table row and Item inner padding (Astryx default density) |
| md | 16px | 4 | Default gap between related elements; Card padding |
| lg | 24px | 6 | Gap between Cards and page sections; AppShell `contentPadding={6}` |
| xl | 32px | 8 | Gap between major page regions |
| 2xl | 48px | `--spacing-12` token only (no `gap` step) | Vertical breathing room around EmptyState and the signed-out screen |
| 3xl | not used | none | Astryx has no 64px token; do not hand-roll one |

Exceptions: none for authored layout. Do not use the half steps `0.5` (2px) and `1.5` (6px) in Counterpoint's own layout (not multiples of 4); Astryx uses them inside its own components and they are left as shipped. Interactive element heights are Astryx `--size-element-sm/md/lg` = 28 / 32 / 36px; default every Button, IconButton and menu trigger to `md` (32px, above the 24px WCAG 2.5.8 floor). Astryx raises the type base to 16px on coarse pointers narrower than `lg` and adds its own touch hit areas; accept that as shipped.

## Typography

Four sizes, two weights. Sizes come from the theme scale (base 14, ratio 1.2) and line heights are the theme's own 4px-snapped values (deliberately not 1.5 / 1.2: Astryx snaps to a 4px grid, so body is 20px on 14px = 1.4286).

| Role | Size | Weight | Line Height | Astryx mapping |
|------|------|--------|-------------|----------------|
| Supporting | 12px | 400 | 1.6667 (20px) | `Text type="supporting"`: timestamps, helper lines, digests, counts under titles |
| Body | 14px | 400 | 1.4286 (20px) | `Text type="body"`: default text, table cells, descriptions |
| Label | 14px | 600 | 1.4286 (20px) | `Text type="label" weight="semibold"`: field labels, card titles, section titles, table headers |
| Heading | 20px | 600 | 1.4 (28px) | `Heading level={2}`: page titles (set `accessibilityLevel={1}` so the page has one `h1`-level heading) and dialog titles |
| Display | 29px | 400 | 1.2414 (36px) | `Heading level={2} type="display-3"`: the **runway number only** |

Rules:
- Declared weights are exactly **400 and 600**. Do not use 500 or 700 in authored text. `Text type="label"` defaults to 500, so always pass `weight="semibold"`. The theme sets `Heading` levels 3 and 4 to bold (700); **do not use `Heading` levels 3-6** — section titles inside cards are `Text type="label" weight="semibold"`. Weights inside Astryx components (a Button's own label is 500) are the design system's and are not overridden.
- Hashes, commit shas, file paths and commands use `Text type="code"` / `CodeBlock` (monospace, 14px, 400). Digests display as the first 12 hex characters; the full value is in a Tooltip and in the copied statement.
- Numbers that change live (runway, counts, plan totals) use `hasTabularNumbers`.

## Color

Theme: `@astryxdesign/theme-neutral@0.7.11`; the app is a light and dark console (FOUND-06). Values are the theme's resolved `light-dark()` pairs (read from the package's built `theme.css`). Always consume them as `--color-*` tokens through Astryx props, never as hex.

| Role | Light / Dark | Token | Usage |
|------|--------------|-------|-------|
| Dominant (60%) | `#f1f1f1` / `#1b1b1b` | `--color-background-body` | Page background behind everything |
| Secondary (30%) | `#ffffff` / `#262626` | `--color-background-surface` | SideNav and TopNav chrome, dialogs, table header band |
| Card fill | `#ffffff` / `#1b1b1b` | `--color-background-card` | Cards and list containers. In dark mode a Card has the **same fill as the body**; it is separated by `--color-border` (`#00000014` / `#ffffff1a`), so keep the border and never set a Card to `elevation` above `none`. |
| Accent (10%) | `#1b1b1b` / `#f1f1f1` (text on it `#ffffff` / `#111111`) | `--color-accent`, `--color-on-accent` | The monochrome accent; see the reserved list below |
| Success | `#198100` / `#64af4c` (text `#2f7d33` / `#90ca90`) | `--color-success`, `--color-text-success` | On runway, check passed, blocked-as-intended probe result |
| Warning | `#ffce2f` (text `#836700` / `#eec448`) | `--color-warning`, `--color-text-warning` | Approved version changed, stale doctor report, live updates paused, uncommitted-edits hint |
| Info | `#0074e2` / `#6d9cfe` (text `#0067ce` / `#a1caff`) | `--color-info`, `--color-text-info` | Ready to approve, not-ready explanations |
| Destructive / error | `#c9303a` / `#ff705d` (text `#c0262c` / `#ffaea7`) | `--color-error`, `--color-text-error` | Failed checks, reachable (unconfined) probe targets, could-not-read errors. **There are no destructive user actions in Phase 1**, so no destructive button is rendered. |

Accent reserved for (explicit list):
1. The single primary Button on a view: "Approve phase" on Phase detail, "Copy command" inside the approval dialog.
2. The keyboard focus ring (`--focus-outline-color` = accent, 2px at 3px offset).
3. The selected SideNav item.
4. The selected segment of the Phase status filter SegmentedControl.
5. The selected radio item in the theme menu.

Never accent: table rows, Badges, links in body text, icons, headings, the runway number, Card borders.

Status is never carried by color alone. Every status pairs a color with an Astryx Badge/Banner text label and an icon (`Icon` from the theme registry).

Phase status vocabulary (derived by core from adapter facts and git; Phase 1 owns only these):

| Status label | Meaning | Badge variant | Icon |
|--------------|---------|---------------|------|
| Not planned | No CONTEXT.md, or CONTEXT.md but no PLAN.md (reason is shown) | `neutral` | circle-dashed |
| Ready to approve | CONTEXT.md and at least one `*-PLAN.md` on the base branch tip, no valid approval | `info` | circle-dot |
| On runway | Valid signed approval, all digests match the base tip | `success` | circle-check |
| Changed since signed | Valid signature but one or more input digests differ | `warning` | triangle-alert |
| Built | Every plan has a SUMMARY.md (nothing left to run); not offered for approval | `neutral` | check |
| Couldn't read | Adapter failed to parse one of its files | `error` | circle-x |

"Built" is a default assumption (not in CONTEXT): D-01 only says phases without plans cannot be approved, but offering "Approve" on an already-built Cena phase would add dead items to the runway. Flagged for the planner in Open Items.

## Copywriting Contract

Voice: plain, second person, short. Say what happened, then the next step. No jargon in the UI that the CLI would not also print (signing commit, base branch tip, digest are named once with a one-line explanation, then used consistently).

| Element | Copy |
|---------|------|
| Primary CTA (Phase detail) | `Approve phase` |
| Primary action in approval dialog | `Copy command` (signing itself happens in the terminal; the dialog never has a "Sign" button) |
| Approval dialog title | `Approve Phase {NN}: {name}` |
| Approval dialog intro | `Run this in your terminal. It asks for your passphrase, then signs a commit on {base} that adds only .counterpoint/approvals/{item}.json. Your uncommitted work is not touched.` |
| Approval dialog waiting line | `Waiting for the signed commit…` (live; becomes `Signed. Runway is now {N}.` when the verified commit appears) |
| Not ready (no CONTEXT) | Badge `Not planned`; Banner (info) title `Not ready to approve`, body `Phase {NN} has no CONTEXT.md yet. Run /gsd-discuss-phase {NN} and /gsd-plan-phase {NN} in Cena, then come back.` |
| Not ready (no plans) | Banner (info) title `Not ready to approve`, body `Phase {NN} has context but no plans yet. You sign the exact plans the builder will run. Run /gsd-plan-phase {NN} in Cena, then come back.` |
| Built phase | Banner (info) title `Already built`, body `Every plan in Phase {NN} has a summary, so there is nothing left to run. Approval is not offered.` |
| Prerequisites banner (warning) | title `Setup needed before the builder can run this`, body lists each `user_setup` item as a bullet, then `{k} of {n} plans need you present (not autonomous).` — shown on the phase **and** at the top of the approval dialog; approval is still allowed |
| Empty: phases list | heading `No phases found`; body `Counterpoint reads {host}'s .planning/ROADMAP.md and found no phases. Check the path with "counterpoint status".` |
| Empty: Needs You | heading `Nothing needs you`; body `If a phase you approved changes after signing, it will show up here with what changed.` |
| Empty: runway (zero) | figure `0`; line `Nothing approved yet. Open a planned phase and approve it to start your runway.` with a Link `Browse phases` |
| Empty: plans in a phase | `No plans yet` (replaces the table; Not-ready banner explains why) |
| Empty: Trust page, doctor never run | heading `Not checked yet`; body `Run "counterpoint doctor" in a terminal. The result appears here.`; the command is in a CodeBlock with copy |
| Error: lists failed to load | Banner (error) title `Couldn't load {phases | Needs You | checks}`; body `Counterpoint's daemon didn't answer. {last good data stays on screen if any}`; action `Try again` |
| Error: live updates lost | Banner (warning) title `Live updates paused`; body `Reconnecting to Counterpoint. What you see may be out of date.` Clears itself on reconnect; no action needed. TopNav connection dot turns warning. |
| Error: not signed in | EmptyState heading `This browser isn't signed in`; body `Run "counterpoint open" in a terminal to get a fresh sign-in link.` (CodeBlock with copy) |
| Error: used or expired sign-in link | EmptyState heading `This sign-in link was already used`; body `Sign-in links work once. Run "counterpoint open" for a new one.` |
| Error: request blocked (Host/Origin/CSRF 403) | heading `Request blocked`; body `Counterpoint only accepts requests from its own console at 127.0.0.1. Open the console from the link "counterpoint open" prints.` |
| Error: can't read a phase | Badge `Couldn't read`; in detail, Banner (error) title `Couldn't read Phase {NN}`, body `{file} could not be parsed: {reason}. Other phases are unaffected. Fix the file in {host}; this page refreshes on its own.` |
| Error: approval refused | Banner (error) inside the dialog, **no command shown**: `Signing would be refused: {host}'s .git/config (or hooks) changed since Counterpoint last checked. Review the change in {host}, then prepare the approval again.` |
| Error: approval stale | Banner (warning) in the dialog: `{base} moved since this was prepared. Prepare the approval again so you sign the current version.` with button `Prepare again` |
| Soft hint: uncommitted edits | Inline Text (supporting) with info icon on the phase row and detail: `Uncommitted edits to this approved phase. The approval only follows what is committed on {base}.` |
| Needs You item title | `Phase {NN} changed since you signed it` |
| Change view lead | `Signed {Timestamp} at {sha7}. {base} is now at {sha7}. {k} input file(s) changed.` |
| Change view action | Section title `Sign the new version`, body `Review what changed, then run:` followed by the same one-line command in a CodeBlock. No sign button. |
| Doctor verdict, all pass | Banner (success) `Agents are boxed in`, body `Checked {Timestamp}. A headless claude session could not read your signing key, ~/.ssh, gh credentials or Counterpoint's state, and could not write {host}'s .git/config, hooks or info.` |
| Doctor verdict, probe fails | Banner (error) `Agent sandbox is not confining sessions`, body `{n} target(s) were reachable. Approvals still work, but builds will refuse to start until this passes.` |
| Doctor stale (over 24 h) | Banner (warning) `This check is {age} old`, body `Run "counterpoint doctor" again.` |
| Probe row result words | Blocked targets: `Blocked` (success badge). Reachable: `Reachable` (error badge). Never "Pass/Fail" for probe rows (a pass means blocked, which reads backwards otherwise). Tool and key checks use `Pass` / `Fail` / `Not checked`. |
| Copy confirmation | Toast `Command copied` (auto-hide) |
| Destructive confirmation | None in Phase 1: no action in the console deletes, revokes or overwrites anything. Re-signing is a terminal action that adds a new signed commit; the console describes it as such. |

## Screens and Layout

Desktop-first (the owner's laptop). Supported down to a 360px viewport via AppShell's built-in mobile nav drawer; there is no bespoke mobile design. Routes are host-scoped from the start (D-06); with one registered host the host switcher shows a single entry and `/` redirects to it.

Routes (IDs validated against the slug regex before use, per the prototype convention):

| Route | Screen |
|-------|--------|
| `/` | Redirect to `/h/{hostId}` (last-used host) |
| `/h/{hostId}` | Mission |
| `/h/{hostId}/phases` | Phases |
| `/h/{hostId}/phases/{phaseId}` | Phase detail (approval dialog opens over it) |
| `/h/{hostId}/needs-you` | Needs You inbox |
| `/h/{hostId}/needs-you/{itemId}` | Approved-version-changed change view |
| `/h/{hostId}/trust` | Trust (doctor report and sandbox probe) |
| `/signed-out` | Signed-out and blocked screens (no AppShell chrome) |

**AppShell chrome**
- `TopNav` `label="Counterpoint"`: `heading` = wordmark text `Counterpoint`; `startContent` = host switcher (DropdownMenu trigger showing host name, e.g. `Cena`, with the base branch as Supporting text `master`); `endContent` = connection `StatusDot` (`success` connected, `warning` reconnecting; label read by screen readers: `Live updates connected` / `reconnecting`) then the theme menu IconButton (`tooltip="Theme"`).
- `SideNav` `label="Main"`, no heading, not collapsible by default (collapsible allowed). Items in order: `Mission`, `Phases`, `Needs You` (with a count badge; hidden at 0, `99+` above 99; the count is also exposed via `VisuallyHidden` text), `Trust`. Selected item uses `isSelected`.
- `contentPadding={6}`. Page body is `Layout` with `LayoutHeader` (title plus page actions) and `LayoutContent`; content is a `VStack gap={6}`. No max width; Tables use the full width, Cards in Grid.
- Browser tab title: `{Page} · Counterpoint`; when Needs You has items, `({n}) {Page} · Counterpoint`.

**Mission (`/h/{hostId}`)** — runway is the headline (MISN-01)
1. Runway card (full width, first): `Display` figure = number of phases on the runway, label (Label) `Runway`, Supporting line `{n} phases · {p} plans approved and ready ahead of the builder`. Below, a List (`Item` rows) of on-runway phases (number, name, plan count, signed Timestamp), each a link to Phase detail. Zero state per Copywriting. If any item is Changed since signed, a Banner (warning) sits directly above the card: `{k} approved phase(s) changed since you signed them` linking to Needs You.
2. Below, `Grid` two columns (one column below `lg`), `gap={6}`: **Needs You** card (up to 5 Item rows, then `View all`) and **Trust** card (one-line verdict from the last doctor report, last-checked Timestamp, link to Trust; verdict uses the same Badge words as the Trust page).
3. The runway figure never moves color; it is not a chart and has no trend in this phase.

**Phases (`/h/{hostId}/phases`)** (ADPT-01)
- Header: title `Phases`; SegmentedControl filter `All`, `Ready to approve`, `On runway`, `Changed` (with counts). All of the host's roadmap phases are listed, ascending by phase number (decimal phases like `01.1` sort in numeric order). There is no QR-menu filter (decided in CONTEXT).
- Table columns: `Phase` (number in code type, then name, `maxLines={1}` with truncation tooltip), `Status` (Badge with icon), `Plans` (`{n} plans`, plus `{k} not autonomous` in Supporting if k > 0), `Setup` (Token `Setup needed` with a Tooltip listing `user_setup` items; blank when none), `Approval` (`On runway · signed {Timestamp}` or `—`). Whole row is a link to Phase detail (keyboard-reachable via the Phase cell link).
- Uncommitted-edits hint renders as a Supporting line under the Status badge.

**Phase detail (`/h/{hostId}/phases/{phaseId}`)**
- Header: Heading (phase number and name), Status Badge, primary Button `Approve phase` (rendered only when status is Ready to approve; otherwise replaced by the matching Banner from Copywriting, and for Changed since signed a secondary Button `Review changes` linking to the Needs You item).
- Order of content: reason/prerequisites Banners, `MetadataList` (goal, depends on, plans `n`, base branch tip sha, signed-by/at when approved), plans Table (`Plan`, `Wave`, `Objective` wraps, `Autonomous` as Yes/No text, `Files` count), then Inputs Card (the covered files with digests; see D-02) so the owner sees exactly what a signature would bind before opening the dialog.
- Plans table with 1 to 20+ rows scrolls with the page (no inner scroll); objective text wraps.

**Approval dialog** (APPR-01; `Dialog purpose="info"`, standard width ~640px)
- Order: prerequisites Banner (if any) → `What you're signing` (MetadataList: phase, base branch and tip sha, plan count) → Inputs Table (`File`, `Digest`: first 12 hex; rows: `NN-CONTEXT.md`, each `NN-*-PLAN.md`, any `*-RESEARCH.md` / `*-UI-SPEC.md` / `*-SPEC.md` / `*-AI-SPEC.md`, and `ROADMAP.md · Phase {NN} section`; footer rows `Draft: none yet` and `Gates: no gate config yet`) → the command in a `CodeBlock` (`language="bash"`, `hasCopyButton`, single line, no wrapping) → waiting/landed status line.
- The command is the ID-only form `counterpoint approve {host} {phase}` (Claude's Discretion; exact shape is a research item). It is only rendered after the server has recomputed and returned the prepared statement.
- Footer: primary `Copy command` (first focus target), secondary `Close`. After the signed commit is observed and verified, the dialog switches to the landed state (success Banner `Signed. Runway is now {N}.`) and its primary becomes `Back to phases`.

**Needs You (`/h/{hostId}/needs-you`)** (MISN-02)
- Single list of `Item` rows (icon, title, Supporting line `{host} · {n} files changed · signed {Timestamp}`), newest first. In Phase 1 the only kind is "approved version changed"; the row component takes a `kind` so later kinds (Phase 2+) reuse it. Each row links to the change view.
- No dismiss, snooze or bulk actions in Phase 1: the item resolves itself when the phase is re-signed or its inputs return to the signed state (state is recomputed from git, never stored as authority).

**Change view (`/h/{hostId}/needs-you/{itemId}`)** — "feels like reviewing a PR" (D-04)
- Lead line from Copywriting, then a Table of changed inputs (`File`, `Change`: Badge `Modified` / `Added` / `Removed`, `Signed digest` → `Now digest`), then one `Collapsible` per changed file whose body is a `CodeBlock isDiff` (maxHeight 480px, horizontal scroll, no wrap; first file open, others closed), then `Sign the new version` with the command CodeBlock. Same landed-state behavior as the dialog if the owner signs while the page is open.
- The diff is between the content at the approval's recorded base commit and the base branch tip now (D-04); text is rendered as plain text, never HTML.

**Trust (`/h/{hostId}/trust`)** (FOUND-03/04)
- Verdict Banner first (Copywriting), then three Cards, each a Table: **Tools** (`claude`, `git`, `gh`: version string, `Pass`/`Fail`), **Signing key** (passphrase-protected; not listed by `ssh-add -L`; not loadable via Keychain: `Pass`/`Fail` plus a fix hint for failures), **Sandbox probe** (rows: `Signing key`, `~/.ssh`, `gh credentials`, `Counterpoint state` with Supporting `cannot read`; `{host} .git/config`, `.git/hooks`, `.git/info` with Supporting `cannot write`; result `Blocked`/`Reachable`).
- Read-only. Re-running is a terminal action (`counterpoint doctor`, command shown in a CodeBlock); the console does not run the probe, so the Trust page has no privileged action.

**Signed-out and blocked screens** (`/signed-out`): centered `EmptyState` on the body background, no AppShell. Used for no session, used/expired link, and blocked requests; copy per Copywriting.

## Interaction Contract

1. **Credential flow (D-07).** The URL printed by `counterpoint` / `counterpoint open` carries a one-time code. The server exchanges it for an `HttpOnly; SameSite=Strict` cookie, then redirects (302) to `/h/{hostId}`; the SPA never sees the code. A code that is used or expired redirects to `/signed-out?reason=used`. Any API 401 sends the SPA to `/signed-out?reason=none`. The SPA must not store or log the code.
2. **Live data.** One SSE stream; UI state is TanStack Query snapshots over HTTP, invalidated by SSE deltas (`runway`, `needs-you`, `phase`, `doctor`, `approval` event families). Reconnect uses `Last-Event-ID`. Never poll. A refresh keeps old rows on screen; skeleton only on first load.
3. **Approve phase.** Click `Approve phase` → dialog opens immediately with Skeletons and `Button isLoading` while the privileged POST asks the server to recompute the statement from the base branch tip (D-03) → on success render the Inputs table and the command; on refusal render only the error Banner. Escape / `Close` dismisses; reopening re-prepares (never reuses a stale statement). While open, the server watches for the signed commit (SSE `approval` event) and flips the dialog to landed; if the base tip moves first, show the stale Banner and disable `Copy command`.
4. **Copy.** `Copy command` copies exactly the printed command string, then fires the `Command copied` Toast and a polite live-region announcement. CodeBlock's built-in copy button does the same.
5. **Theme.** `Light`, `Dark`, `System` (default `System`) in a DropdownMenu with radio items; choice persisted in `localStorage` key `counterpoint.theme`, applied through `<Theme mode>`. To avoid a first-paint flash, set `data-theme` on `<html>` from `localStorage` in a tiny **external** script (`/theme-init.js`, loaded synchronously in `<head>`; inline script is blocked by the CSP). Both themes ship with identical layout; only tokens change.
6. **Navigation.** Standard links and SideNav only; no modals-on-modals; browser Back always works; selected nav reflects the current route. No keyboard shortcuts in Phase 1.
7. **Motion.** Use Astryx's themed motion as shipped (neutral: fast 125ms / medium 300ms). Honor `prefers-reduced-motion` (Astryx does this through the Theme); add no custom animation. The only continuously animated element is the `StatusDot isPulsing` while reconnecting.
8. **Privileged calls.** Every non-GET sends the session cookie and passes the server's Origin check; the SPA treats 403 as the `Request blocked` screen and 401 as signed out. No token is ever placed in the URL after the first exchange.

## Accessibility

- AppShell's skip link, banner and main landmarks are used as shipped; TopNav and SideNav each get a distinct `label`.
- One page-level heading per route (the `Heading level={2} accessibilityLevel={1}` title); section titles inside Cards are labels, not headings 3-6 (see Typography), so use `Section`/`Card` with an accessible name instead of relying on heading depth.
- Status never by color alone (icon plus word). Probe rows read "Blocked" / "Reachable", never color-only.
- Live changes (runway count change, a new Needs You item, approval landed, reconnecting/reconnected) are announced politely with `useAnnounce`; the approval dialog's landed state is announced once.
- Focus: dialog opens with focus on `Copy command` (or the error Banner's first action on refusal) and returns to `Approve phase` on close. Focus ring is Astryx's `:focus-visible` outline in accent.
- Contrast: all text pairs come from the theme's tokens (primary and secondary text meet 4.5:1 on body and surface in both modes; status text tokens are the 4.5:1 roles). Do not place `--color-text-secondary` on `--color-accent` or any status fill; use the matching `--color-on-*` token.
- Tables have real header cells; sortable columns are not required in Phase 1 (static order by phase number). Truncated text is always reachable via Tooltip and in the detail page.
