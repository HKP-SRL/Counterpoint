<objective>
Gap closure 2 of 3 after the halted 01-18 (G4, plus 01-18's Trust page slice).

01-21 moved agent sessions to auto mode. On claude 2.1.321 the halted 01-18 run showed that claude can silently override the mode Counterpoint asks for. It printed `⚠ Permission mode forced to default …` on stderr and `permissionMode: "default"` in the init event. So `counterpoint doctor` must check the mode the probe's agent session really ran in, not the mode it was launched with. A future claude upgrade then cannot change the mode without failing doctor.

This plan records the effective mode from the treatment's init events, cross-checked with stderr, as an additive `agentMode` check in the `counterpoint/doctor/v1` report. Doctor fails anything but `auto`, the CLI prints it, and the Trust page shows it. The same Trust page change adds 01-18's unfinished slice: the eighth probe row and the updated all-pass wording, with the UI contract to match (Astryx only).

Purpose: success criterion 2 / FOUND-03. Doctor's pass must describe the configuration Phase 2 will really run, including its permission mode.
Output: the mode evidence reader, the report field and verdict rule, the doctor CLI line, the Trust page rows and wording, UI-SPEC E8, and green unit and e2e suites.
</objective>

**Design notes:**
- *Where the mode comes from.*
  - Every `system/init` stream event carries `permissionMode`. The 01-18 evidence shows `"default"` with the forcing notice on stderr; 01-21's evidence shows what auto looks like (read its SUMMARY).
  - The treatment may run twice (a retry when a step was skipped), so every init event counts.
  - stderr is a cross-check: any line matching /permission mode|auto mode/i is a notice and fails the check, even if init said `auto` (fail closed).
- *Why a check row, not a probe row.* The mode is a property of the session, not a protected target. It renders like the other checks (`Pass`/`Fail`/`Not checked`) at the top of the Sandbox probe card, so probe rows keep their `Blocked`/`Reachable` words.
- *Schema stays v1.* `agentMode` is optional in zod, so older reports still parse. `reportVerdict` fails when it is missing or not `pass`, and the Trust page counts a missing one as not passing.
- *Single source for the expected mode.* `AGENT_PERMISSION_MODE` (src/agent/claude-argv.ts, 01-21) is what the argv launches with, and doctor passes it as `expected`. Core (doctor-report.ts) receives it as a parameter, so core still imports nothing from `src/agent/`.
- *Between Task 1 and Task 2.* Task 1 changes the server verdict, so the e2e fixtures that expect `Agents are boxed in` only pass again after Task 2 adds `agentMode` to them. Task 1 verifies with the unit project, and Task 2 runs both projects.
